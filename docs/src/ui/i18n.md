# GUI/WebUI i18n

本文记录 `klaw-gui` 与 `klaw-webui` 的国际化实现。当前目标是让桌面端和 Web 端都支持 English 与简体中文，English 是默认语言和 fallback 基准。

## 范围

当前 i18n 覆盖的是：

- `klaw-gui` 顶部菜单栏
- `klaw-webui` 顶部菜单栏
- `klaw-webui` 顶部连接状态标签
- GUI 与 WebUI 的语言选择入口

其他面板正文、提示、对话框文案仍可能是英文，这是有意的分阶段范围。后续扩展时应继续使用同一套语言类型和 Fluent 资源，不要引入第二套翻译机制。

## 共享基础设施

i18n 基础设施放在 `klaw-ui-kit`：

- `klaw-ui-kit/src/locale.rs` 定义 `UiLanguage`、`LocaleDomain` 和 `Translator`
- `UiLanguage` 目前只包含 `English` 与 `SimplifiedChinese`
- `LocaleDomain` 区分 `Gui` 与 `WebUi`
- `Translator` 负责按 domain + language 读取嵌入式 Fluent 资源
- 缺失翻译先回退 English，English 仍缺失时返回 key 本身

资源通过 `rust-embed` 嵌入程序，并由 `i18n-embed` 的 Fluent loader 加载。为了避免 egui 每帧重复解析 Fluent 文件，`Translator` 内部使用按 domain/language 组合缓存的 loader。

相关依赖集中声明在 workspace：

- `i18n-embed`，启用 `fluent-system`
- `rust-embed`
- `unic-langid`

`klaw-ui-kit/Cargo.toml` 按目标平台启用 requester feature：

- desktop: `desktop-requester`
- wasm32: `web-sys-requester`

当前产品行为不使用自动系统语言检测，语言由用户显式选择；requester feature 主要保证桌面与 WASM 目标具备同一套依赖能力。

## 资源布局

GUI 与 WebUI 不共享同一个 `.ftl` 文件。两边界面不同，强行共用 key 会让命名变模糊，也会让后续翻译互相牵制。

当前资源结构：

```text
klaw-ui-kit/locales/
├── en-US/
│   ├── gui.ftl
│   └── webui.ftl
└── zh-CN/
    ├── gui.ftl
    └── webui.ftl
```

约定：

- `gui.ftl` 只放桌面 GUI 需要的 key
- `webui.ftl` 只放 WebUI 需要的 key
- English 文件必须包含 fallback 基准文案
- 简体中文文件可以少量缺 key，但缺失时会显示 English
- key 使用语义命名，例如 `menu-file`、`menu-gateway-token`、`status-connected`

## GUI 集成

GUI 语言偏好保存在 `~/.klaw/settings.json`，不写入 `~/.klaw/config.toml`。

相关文件：

- `klaw-gui/src/settings.rs`
- `klaw-gui/src/panels/setting.rs`
- `klaw-gui/src/ui/shell.rs`

`GeneralSettings` 包含 `ui_language: UiLanguage`，默认值是 English。加载 settings 时会同步一个进程内当前语言缓存，顶部菜单渲染从这个缓存读取语言，避免每帧读磁盘。

Settings 面板的 `General` 区域提供语言下拉框。保存语言时使用专用 helper：先读取最新 settings 文件，只合并 `general.ui_language`，再写回。这避免 Settings 面板持有旧快照时覆盖其他路径刚写入的设置。

顶部菜单使用 GUI domain：

```rust
let translator = Translator::new(LocaleDomain::Gui, current_ui_language());
ui.menu_button(translator.text("menu-file"), |ui| {
    // ...
});
```

## WebUI 集成

WebUI 语言偏好保存在浏览器 `localStorage` 的 workspace state 中，不依赖后端配置。

相关文件：

- `klaw-webui/src/web_chat/storage.rs`
- `klaw-webui/src/web_chat/app.rs`
- `klaw-webui/src/web_chat/ui.rs`

`PersistedWorkspaceState` 包含 `ui_language: UiLanguage`，默认值是 English。`ChatApp` 持有当前语言，并通过 `set_ui_language()` 更新状态、持久化并请求重绘。

WebUI 有两个语言入口：

- 底部状态栏语言下拉框
- `File > Settings` 弹窗里的语言下拉框

两者都写入同一个 `ChatApp::ui_language`，因此刷新页面后会恢复选择。

顶部菜单和连接状态使用 WebUI domain：

```rust
let translator = Translator::new(LocaleDomain::WebUi, self.ui_language);
ui.menu_button(format!("{} {}", regular::FILE, translator.text("menu-file")), |ui| {
    // ...
});
```

## 测试与验证

`klaw-ui-kit` 覆盖共享语言层：

- 默认语言是 English
- `UiLanguage` 显示标签
- GUI/WebUI 分域翻译
- 简体中文缺 key 时回退 English

`klaw-gui` 覆盖 settings 演进：

- 旧 JSON 缺少 `ui_language` 时默认 English
- 保存语言时重新读取最新 settings 并只合并语言字段，避免覆盖其他设置

`klaw-webui` 的 `web_chat` 模块是 `wasm32` gated，普通宿主测试不会覆盖 UI 渲染路径。验证 WebUI 时至少运行：

```bash
cargo test -p klaw-webui
cargo check -p klaw-webui --target wasm32-unknown-unknown
```

完整变更还应运行：

```bash
cargo test -p klaw-ui-kit
cargo test -p klaw-gui
cargo check --workspace
```

## 扩展指南

新增翻译文案时：

1. 判断文案属于 GUI 还是 WebUI，放入对应 `.ftl` 文件。
2. 先给 `en-US` 添加 key，再给 `zh-CN` 添加对应翻译。
3. 调用 `Translator::new(LocaleDomain::Gui, language)` 或 `Translator::new(LocaleDomain::WebUi, language)`。
4. 不要为了复用而创建含义模糊的通用 key。GUI 与 WebUI 可以使用同名 key，但语义必须在各自 domain 内清晰。
5. 如果新增参数化文案，再给 `Translator` 增加对应的局部 API 和单元测试。

不要把 UI 语言偏好写入 `~/.klaw/config.toml`。该文件是运行时共享配置，GUI/WebUI 的界面语言属于前端偏好，应继续使用各自已有持久化位置。
